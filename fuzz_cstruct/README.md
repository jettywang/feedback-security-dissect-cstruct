
# 模糊测试方案：dissect.cstruct 后端（接收第三方结构描述）

本目录是一套**自包含、确定性、固定次数内必然退出**的模糊测试演示，目标不是向
`read()` 扔随机字节，而是同时模糊“结构定义解析”和“二进制解析”，找出只有两者
**组合**后才暴露的问题。

## 1. 为什么不能只模糊字节流

`dissect.cstruct` 的输入分两层：

1. **定义层**：C 风格的 `typedef` / `struct` / `enum` / 数组长度表达式，经
   `CStyleParser` 词法、语法解析，再做别名解析、类型解析、表达式构造；
2. **二进制层**：定义产出的类型对象对字节流执行 `read()`。

随机字节几乎全部死在定义层的词法/语法阶段，永远到不了“某个动态数组长度由流里
读到的字段决定”这类组合逻辑。本方案因此把熵放在**结构化定义**上，字节流只
提供一个**短小、带读取上限**的确定性缓冲。

## 2. 四个关联阶段

每个用例（`case_model.Case`）按下面四个阶段建模，变异器只替换同一种语法槽位，
从而保持“部分语法合法”（能被词法/语法接受，但可能语义非法）。

| 阶段 | 名称 | 对应代码路径 | 典型变异 |
|----|----|----|----|
| 1 | 别名解析 | `cstruct.add_type` / `resolve`、`typedef` | 别名指向未定义类型、别名循环 A↔B、别名链末端悬空 |
| 2 | 前向类型引用 | 命名 struct 预注册、`cs.resolve(name)` | 永不补全的前向声明、按值自引用、跨结构按值互引 |
| 3 | 数组长度表达式 | `Expression`（shunting-yard）、`BaseArray._num_entries` | 未定义名字、`1 << n` 极端移位、除零、`sizeof/offsetof`、EOF |
| 4 | 编译回退 | `compiler.compile_structure` 失败后回退解释器；LEB128/自定义类型 | 插入不可内联类型、嵌套静态结构 + 截断流 |

阶段 4 同时是**差分测试**的支点：同一用例分别以 `compiled=True`（生成并编译
Python 源码，失败透明回退）和 `compiled=False`（纯解释执行）运行。

## 3. 保持部分合法的变异

见 `case_model.py`。变异在 AST 级的“槽位”上进行，而不是字符翻转：

- 替换数组长度表达式（仍产出合法的 `field[expr]` 语法）；
- 替换 typedef / 前向声明整行（仍是合法声明语法，但名字可能不可解析）；
- 切换内建类型宽度、插入 LEB128 等回退类型；
- 小概率注入“嵌套静态结构 + 短流”差分用例。

因此用例要么合法执行，要么以**语义错误**失败（未定义标识符、循环依赖、资源
超限），而不是产生无意义的词法噪声。

## 4. 能独立判断错误的 Oracle

`oracle.py` 在两个全新的 `cstruct` 实例上分别执行同一用例，独立观察
`load`（定义解析）与 `read`（二进制解析）两个阶段，并给出四类判定：

- **ok**：两模式都成功，且值的结构化摘要一致；
- **illegal（输入不合法）**：两模式在**同一阶段**以**同一异常族、同一语义签名**
  拒绝。这是输入本身的问题，不是库缺陷；
- **diverge（两种执行模式不一致）**：成功/失败不同、异常阶段或族不同，或异常族
  相同但**语义细节**不同；
- **dos（真实拒绝服务风险）**：资源守卫被触发，与具体模式无关。

关键细节：`EOFError` 消息里的“期望字节数”会被保留进语义签名。编译器把嵌套
静态结构合并成一次整块 `unpack`（报整个块大小），解释器逐字段读（报第一个缺失
字段大小）。两者都是 read 期 `EOFError`，但期望字节数不同——若只比较异常类名
会被错误归为 illegal，本方案据此正确识别为 diverge。

## 5. 终止策略（不会耗尽资源）

三类危险构造各有独立的有界手段，见 `guards.py`，且都不修改被测库：

- **表达式未定义名字**：库自身快速抛 `UnknownIdentifierError`；移位过大时 Python
  自身抛 `OverflowError`（“cannot fit int into index-sized integer”），均为即时失败；
- **循环类型依赖**：`recursion_ceiling()` 在试验期间把递归上限临时降到 300，
  无限嵌套迅速变成 `RecursionError`，而非真正的栈崩溃，结束后恢复原值；
- **极端移位 / 超大 count**：
  - `time_budget()` 用 `SIGALRM`/`setitimer` 给每次试验 2 秒墙钟硬上限；
  - `CappedStream` 把超过 1 MiB 的 `read(n)` 请求转为 `StreamBudgetExceeded`，
    避免库在短流上尝试巨型 `struct` 格式或列表分配。

字节流本身固定且很小（默认 64 字节，最小样本可短至 5–8 字节），所有“巨大”都
由定义驱动并在守卫处被截断。整个 campaign 固定迭代次数（默认 120），必然退出。

## 6. 三类失败如何区分

| 判定 | 判别条件 | 最小样本 |
|----|----|----|
| 输入不合法 | 两模式同阶段、同异常族、同语义签名 | `minimal_illegal.txt`：长度表达式引用不存在的字段 `nope`，两模式均 `UnknownIdentifierError` |
| 模式不一致 | 异常族相同但语义签名不同（或成败不同） | `minimal_diverge.txt`：嵌套静态结构 + 5 字节截断流，编译报 `expected 12`、解释报 `expected 4` |
| 真实 DoS | 守卫触发（时间/读取上限/内存/递归） | `minimal_dos.txt`：流中 `n=60`，`data[1 << n]` 请求 2^60 字节，触发 `StreamBudgetExceeded` |

注意：异常的**存在**本身从不被当作缺陷；只有跨模式差异（diverge）或资源守卫
触发（dos）才是需要上报的信号。

## 7. 缩减规则

`reducer.py` 在结构化 `Case` 上做有界 delta-debug，候选必须满足“判定不变且渲染
长度变短”才被接受，最多固定趟数，保证终止：

1. 逐条删除仍未被字段引用的 `typedef`；
2. 逐条删除仍未被字段引用的前向声明；
3. 用更短表达式替换数组长度（保留能维持判定的最简形式）；
4. 从末尾删除非必要字段，始终保留首个长度字段。

规则 1/2 会保护失败根因：仍被存活字段引用的别名/前向声明不会被删，避免最小
样本退化成“因另一个无关原因而失败”。

## 8. 目录与运行

```
fuzz_cstruct/
├── guards.py        # 时间/递归/读取上限三类守卫
├── case_model.py    # 四阶段 Case 模型 + 部分合法变异器
├── oracle.py        # 双模式差分 oracle 与四类判定
├── fuzzer.py        # 固定次数、确定性的语料生成循环
├── reducer.py       # 有界 delta-debug 缩减器
├── samples.py       # 三个可读最小样本
├── corpus_writer.py # 生成并落盘语料
├── test_fuzz.py     # 工具链契约测试（10 项）
└── corpus/          # 最小样本 + 去重后的缩减发现
```

```bash
# 固定 120 次，默认在 1 秒内完成
python -m fuzz_cstruct
python -m fuzz_cstruct -n 40 --findings     # 只看非 OK 用例
python -m fuzz_cstruct.corpus_writer         # 重新生成 corpus/
python -m pytest fuzz_cstruct/test_fuzz.py   # 契约测试
```

## 9. 已验证的库行为（探针结论）

- 未定义名字、除零、负移位、跨类型按值互引等在两模式下**表现一致**，归 illegal；
- 静态超大数组的成本主要在加载期构建默认值（与是否编译无关），动态超大 count
  在短流上通常快速 EOF——真正稳定可复现的 DoS 信号来自“流控移位 + 读取上限”；
- 唯一在本仓库版本上稳定观察到的自然差分，是嵌套静态结构截断时的 EOF 期望字节数
  差异（packed 整块读 vs 字段级读）。这是 oracle 设计价值的实证，而非随机撞库。
